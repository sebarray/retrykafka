Usando el contexto global de `retrykafka`, implementar `v0.6.0`.

# Objetivo

Agregar idempotencia opcional.

Implementar:

```text
Idempotency core interface
PostgreSQL adapter
```

# Core

Diseñar una interfaz estable.

Estados:

```text
PROCESSING
COMPLETED
FAILED
```

La operación inicial debe ser:

```text
Atomic Claim
```

Nunca:

```text
Exists
→ Process
→ Save
```

# Message Identity

Por defecto utilizar:

```text
x-message-id
```

como idempotency key.

Permitir custom key extractor.

# Crash Recovery

Resolver:

```text
Consumer claims PROCESSING
      │
      ▼
Process crashes
      │
      ▼
Message redelivered
```

No permitir PROCESSING infinito.

Implementar una estrategia de:

```text
Lease
or
Processing Timeout
```

Documentar la semántica exacta.

# PostgreSQL

Crear adapter separado.

Utilizar:

```text
Unique constraints
Atomic insert
Transactions where appropriate
```

No acoplar el core al driver.

# Testing

Usar:

```text
Unit tests
Testcontainers
PostgreSQL integration tests
Race detector
```

Probar:

```text
Duplicate message
100 concurrent claims
Completion
Failure
Lease expiration
Crash recovery
Multiple consumers
```

Documentar trade-offs.
