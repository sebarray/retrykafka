Usando el contexto global de `retrykafka`, implementar `v0.4.0`.

# Objetivo

Agregar structured logging usando:

```text
log/slog
```

# Default

Usar:

```go
slog.Default()
```

Permitir:

```go
retrykafka.WithLogger(logger)
```

# Eventos

Loguear:

```text
Message received
Message processed
Processing failed
Retry scheduled
Retry published
DLQ published
Offset committed
Consumer shutdown
Publisher error
```

# Attributes

Agregar:

```text
message_id
topic
partition
offset
retry_attempt
max_attempts
error
```

No incluir payload completo por defecto.

# Concurrencia

El logger puede ser utilizado desde múltiples goroutines.

No asumir un logger no thread-safe.

Documentar las expectativas.

# Testing

Agregar un handler de testing para verificar:

```text
Eventos
Attributes
Errores
Retry lifecycle
DLQ lifecycle
```

El logging no debe alterar el comportamiento funcional.

Documentar el trade-off entre observabilidad y volumen de logs.
